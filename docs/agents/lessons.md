# Lessons — flutter_table_plus 실증

이 repo 가 실제로 **무엇을 놓쳤나** 의 기록 — 규칙에 무게를 주는 근거. 전부 이 repo 에서
실제로 일어났다. `CLAUDE.md` 나 MAP 의 invariant 노트가 추상으로 읽히면 여기 사건과
대조하라 — 규칙이 사는 곳은 그 둘이고, `docs/agents/thegraph.md` 는 이제 바깥 참조원만
들고 있다. 새 실증은 해당 단계 밑에.

아래 `Step N` 은 은퇴한 `theflow` 에서 물려받은 번호지만, 이제 이 파일 **자신의** 목차다.
바깥 어디와도 대조하지 마라 — 대조할 것이 이미 없다.

---

## Step 1 — 이슈 먼저 (관찰은 적고, 진단은 확정하지 마라)

이슈 본문은 *관찰을 적는 곳*이지 원인을 단정하는 곳이 아니다. 확정한 진단이 틀리면 다음
사람이 그걸 믿고 엉뚱한 데를 판다.

- **#55**: "playground 가 800×600 테스트 표면에 안 맞으니 뷰를 키워라" 라고 못박았다.
  2000×1200 으로 키워도 실패 — 설정 패널이 `width: 380` 고정이라 제약은 `0<=w<=305` 그대로.
  진짜 원인은 테스트 폰트였다(Step 2).
- **#62**: "섹션이 안 접히니 #59 로 먼저 위젯을 갈라야 한다" 라고 썼다. `buildSection` 은
  **이미 `ExpansionTile`** 이었다 — 파일 *줄 수*만 보고 *내용*을 안 읽은 결과. 정정하고
  blocker 를 뗐다.
- **#65**: "오버플로가 12 곳" 이라 추정했다. 실패 스택을 소스 줄로 집계하니 **34 건이
  정확히 두 줄**(공용 헬퍼 둘)에서 났다. **결함 수는 인스턴스 수가 아니다.**
- **#63**: 아무것도 단정하지 않고 *"#61 이 끝난 뒤 읽고, 결정을 이유와 함께 기록하라"* 로
  썼다. 넷 중 유일하게 맞았다 — **판단을 유예하는 이슈는 정당한 형태다.** 닫는 이슈엔
  재개 조건을 남긴다(닫힌 이슈는 검색되지만 읽히지 않는다).
- **#113 (검사기를 의심하라 — 모든 후보가 같은 답을 내면 특히)**: 레시피 줄바꿈을
  `grep -c $'\r'` 로 세어 *"194 CR / 194 줄, 전부 CRLF"* 라고 적었다. **빈 패턴이 모든 줄에
  매칭된 것**이었고, 실제로는 **CRLF 6 / LF 5 혼합**이며 근거로 든 `selection_recipe.dart` 는
  LF 였다. 파일마다 CR 수가 줄 수와 정확히 일치한 것이 신호였다 — Step 7 의 *"전부 실패하거나
  전부 성공하면 검사기를 의심"* 이 측정 도구 일반에 적용된다. 바이트로 다시 셌다.
  덤: `.gitattributes` 가 `* text=auto` 라 **줄바꿈 구성은 체크아웃의 속성이지 repo 의 속성이
  아니다** — 코퍼스를 픽스처로 쓰는 테스트는 그 사실을 스스로 단언해야 한다.
- **#60 (위치가 의존성을 숨긴다)**: `_settings`/`_columns`/`context` 만 훑고 "순수하다" 고
  판단했으나, 옮기자 `_formatNumber`·`_getPerformanceColor` 가 없다고 했다. 둘 다 인자만
  받는 순수 함수였다. **위치가 의존성을 만들지 않는다 — 다만 숨긴다.** 옮기기 전 grep.

## Step 2 — 경계 / 우회 금지 (원인은 `pubspec` 바깥일 수 있다)

`just_tooltip`·`flutter_checkbox` 는 남의 코드가 아니다 — 소스는 `../` 에 있고 각자 트래커가
있다. 동작이 궁금하면 그 소스와 CHANGELOG 를 읽는다.

- **#33 (우회는 결함을 숨긴다)**: 행 툴팁이 `child` 앵커를 피해 `pointer` 로 우회했고 잘
  작동했다. 그래서 upstream 결함이 살아남았다 — just_tooltip 0.4.2 CHANGELOG: *"both known
  downstreams had independently adopted it as a workaround."* **우회가 잘 들을수록 결함은
  오래 산다.** 0.4.2 가 고치자 이 리포 여섯 곳의 근거가 한꺼번에 거짓이 됐다.
- **#88 → #96 (판정과 보고는 별개의 의무다)**: `MouseRegion.onEnter` 의 조상 억제는
  0.4.0(#22)이 *의도한 계약*이라 판정하고, 그릴 게 없는 툴팁을 지은 이쪽을 고쳤다 — 판정은
  옳았다. **그러나 upstream 에 보고하지 않았다.** just_tooltip 0.4.4 가 같은 지점을 자기
  결함으로 판정하며 적었다: *"Two packages had independently grown the same local guard
  rather than report it."* 잘 드는 우회가 그 침묵을 정당해 보이게 만들었다. 로컬 가드는 이제
  제거됐고(#96) `^0.4.4` floor 가 그 자리를 대신한다 — **재도입 금지.**
- **#69/#38 (양방향 막)**: upstream 이 Flutter 3.13 을 요구하자 이쪽 `environment` 가 따라
  올라가야 했다. 변경은 아래로만 흐르지 않는다. `^0.4.0` 은 0.4.2 를 이미 해석하므로
  `>=3.10.0` 선언이 3.10~3.12 사용자에게만 깨졌다 — `pub get` 성공은 제약이 정직하다는
  증거가 아니다.
- **2.16.0 (dep 의 floor 상승은 우리한테 BREAKING 이다 — 코드가 안 바뀌어도)**: 사용자가
  `flutter_checkbox` 0.2.1→0.3.0 을 *"0.0.1 패치"* 로 인식했다. 그러나 0.3.0 은 자기 floor 를
  `flutter create` 기본값(`>=1.17.0`)에서 진짜 최소값(`Dart ^3.9.2` / `Flutter >=3.35.0`)으로
  **교정**했고, `^0.3.0` 을 잡는 순간 3.35 가 우리의 transitive 요구가 됐다. `lib/` 는 한 줄도
  안 바뀌고(0.3.0 은 순수 가산, 마지막 제거는 0.2.0 — 이미 그 위) 382+67 테스트가 무수정
  통과했지만, **pub 패키지의 semver 는 API 뿐 아니라 선언된 SDK 범위도 포함한다.** min-SDK
  상승은 이전 SDK 사용자에게 BREAKING → minor 범프 + `BREAKING` 라벨(2.15.0 의 3.10→3.13
  선례와 동일). #69 와 다른 점: 거기선 *우리* `^0.4.0` 제약이 이미 높은 버전을 조용히 해석했고,
  여기선 *upstream 이 자기 거짓 floor 를 고쳐서* 우리를 끌어올렸다. **트립와이어**: "버전만
  올려줘" 요청이 와도 dep CHANGELOG 의 `environment:` / floor 변경을 먼저 읽어라.
- **웹 성능 (2026-08, 원인이 repo 바깥·`pubspec` 바깥일 수도 있다)**: 셀/행당 선할당은
  실재했다 — `just_tooltip` 은 `initState` 에서 `AnimationController`+`Ticker`+`TickerMode`
  리스너를(`just_tooltip.dart:337-347`), `flutter_checkbox` 는 `AnimationController` **2 개**를
  (`checkbox_animation.dart:24-38`) 보여주지도 않을 위젯에 미리 짓는다. 그런데 `--wasm` 이
  그 비용의 대부분을 흡수했다: WasmGC 에서 `minimal`(1.29ms)과 `default`(1.34ms) 차이가
  사실상 사라진다. **JS 할당 비용이었지 구조 비용이 아니었다.** 두 upstream 의 지연 초기화는
  여전히 옳지만(둘 다 우리 패키지다) 우선순위는 내려갔다 — **upstream 을 고치기 전에 그
  비용이 어느 층에서 나는지부터 재라.**

## Step 4/5 — 증명 & 테스트 신뢰 (구분력 + 옳은 이유)

- **테스트 폰트는 글자당 `fontSize` 정사각형** — 오버플로가 화면보다 훨씬 쉽게 난다. #55:
  19자×16 = 304 vs 실제 ~190. **성가신 게 아니라 텍스트 폭 최악 경우 시뮬레이터** — 접근성
  확대가 도달할 자리를 미리 밟는다.
- **#121 (허용오차가 잡아야 할 오차와 같은 크기면 그건 눈가리개다)**: 병합 그룹 멤버가
  측정 높이를 무시하고 총합을 균등분할하던 결함. 첫 수정은 측정 높이에 **비례하는 flex** 였고
  테스트는 `closeTo(±1.0)` 으로 초록이었다. 그런데 `1.0` 은 `dividerThickness` 기본값과
  **같은 숫자**이고, 그게 정확히 그 메커니즘이 만드는 오차의 크기였다 — 두 렌즈가 독립적으로
  같은 곳에 도달했다. `dividerThickness: 4` 로 올리자 case 1 이 빨개졌다(멤버 c, 156.0 기대
  154.0 실측). **임의로 고른 "넉넉한" 허용오차는 근거가 없는 허용오차다.** 지금은 잔차를
  등식으로 못박는다: `ungrouped − grouped == kT/2`.
- **#121 (`Container` 의 `BoxDecoration` border 는 자식 공간을 먹는다)**: 그룹 상자는
  `mergedHeight` 인데 그 안의 `Column` 이 받는 건 `mergedHeight − dividerThickness`.
  그래서 멤버들에 고정 높이를 합쳐 넣으면 정확히 1.00px 넘친다. **균등분할은 그 차이를 조용히
  흡수하고 있었고, 그게 결함이 "작동하는 것처럼 보인" 이유의 일부다.** 부족분을 비례로
  퍼뜨리면 모든 멤버가 어긋나고, border 는 그룹 **아래쪽**에 있으니 그 셀만 flexible 로 두면
  나머지는 정확히 맞는다. 배치 판단은 물리적 위치를 따라간다.
- **#121 (틀린 *이유*는 어떤 테스트도 잡지 못한다 — 세 개를 한 번에)**: 수정과 함께 쓴 주석
  셋이 전부 틀렸고 스위트 428 개는 전부 초록이었다. ① "tallest 값이 인라인 에디터 크기를
  정한다" — 부모가 tight 제약을 주므로 **죽은 인자**(멤버 자기 높이를 넣어도 428 초록).
  ② "높이 합이 총합과 정확히 같으니 넘칠 수 없다" — 1.00px 넘친다. ③ "`flex: 0` 이면 공간을
  전혀 못 받는다" — `RenderFlex` 는 flex 0 자식을 **flex 자식으로 치지 않고** main axis 를
  unbounded 로 둔다(내용만큼 차지하고 남을 줄인다). 가드는 옳았고 기록된 이유가 반대였다.
- **#121 (변이가 초록이면 테스트가 아니라 그 assertion 의 주어를 의심하라)**:
  `calculatedHeight + 10` 이 아무것도 빨갛게 못 만들었다 — 그룹의 리스트 슬롯은 **다른 도출**
  (`_getMergedGroupExtent`)이 정하고 그게 Container 를 클램프하므로, 틀린 `calculatedHeight`
  는 렌더된 rect 에 도달조차 못 한다. 대체로 넣은 "그룹 자기 높이" assertion 도 같은 이유로
  vacuous 였고 **유지가 아니라 삭제**했다. assertion 의 주어를 총합을 실제로 소유하는 도출로
  옮기니 빨개졌다.
- **#58 (`find.text` 는 화면 어디든 잡는다)**: 홈이 없는데 `find.text('Playground')` 가
  통과 — `settings_panel.dart` 헤더가 같은 문자열을 그린다. 흔한 단어 단언은 아무것도 말 안 함.
- **#59 (이름이 아니라 개수를 세라)**: 컨트롤 68 개를 `Switch 25 / Dropdown 12 / Slider 20`
  개수로 덮었다. 이름으로 못박았다면 섹션 이동마다 테스트를 고쳐야 했고 "안 바뀌었다" 는
  순수성 증거가 사라졌다. 개수는 20→21 로 정직하게 깨진다.
- **#62 (관찰 지점을 화면에)**: `find.byType(ExpansionTile)` 은 위젯을 갈아끼우자 즉시
  깨졌고, `find.byIcon(Icons.expand_more)` 는 살아남았다. **리팩터 생존은 관찰 지점 위치로
  결정된다.**
- **#50/#52 (의미 가드 ≠ 회귀 가드)**: `scaledBy leaves an unset X tooltip theme unset` 은
  수정 없이도 통과한다(필드를 떨어뜨려도 `null`). 회귀를 잡는 건 `carries ... through
  untouched` 쪽. 커밋 메시지에 어느 쪽인지 적는다.
- **순수 이동 전 특성화 테스트 = 발견 도구.** #59: 그걸 쓰다 `ExpansionTile` 존재와 오버플로
  34 건을 찾았다. 리팩터 전 사진 한 장이 #59(그물)·#65(red 장치)·#62(계약)로 세 번 값했다.
- **#50 (그물 치지 말고 절벽 없애라)**: `scaledBy()` 가 `TablePlusTheme` 필드를 손으로
  나열해 재구성하다 `rowTooltipTheme` 를 잃었다. 리뷰가 지적해 `copyWith` 위에 다시 썼다 —
  스케일하는 여섯 필드만 부르니 나머지는 열거되지 않아 떨어뜨릴 수 없다. `scaledBy(1.0)` 이
  수신자를 그대로 돌려줘 버그가 안 보였다.
- **웹 성능 (2026-08, 개수는 시간이 아니다)**: "웹 스크롤이 버벅인다" 를 코드로 읽어
  1 순위를 **툴팁**으로 지목했다. 근거는 참이었다 — bare 테이블에서 셀 70 개 : `JustTooltip`
  70 개(1:1). `table_column.dart:108-109` 의 `textOverflow.ellipsis` × `TooltipBehavior.always`
  기본값이 겹쳐 `TooltipResolver.shouldShow` 가 비지 않은 모든 텍스트 셀에서 참이 된다.
  그런데 headless Chrome 실측에서 툴팁 몫은 6 컬럼 `default` 5.45ms 중 **+0.25ms** 였다.
  실제 1 순위는 `isSelectable`(+1.63ms), 그마저도 답이 아니었다 — **빌드 모드**(debug 가
  release 의 2.1~2.5 배)와 **`--wasm`**(canvaskit 대비 2.6~3.1 배)이 답이었고 둘 다 패키지

  고치지 않고도 덮이는가.**

- **#171 (`redden` 이 거짓 초록을 냈다 — 변이가 애초에 적용되지 않아서)**: 수정을 문자열
  치환으로 되돌려 테스트가 빨개지는지 봤는데 통과했다. "내 단언이 아무것도 고정 못 한다"로
  판단할 뻔했으나, 실제로는 그 사이 `dart format` 이 대상 줄을 세 줄로 감싸놔서 **치환이
  아무것도 매치하지 않은** 것이었다. `assert old in s` 를 걸고 다시 하니 461/461/461 이
  나왔다. **변이가 적용됐다는 것 자체를 단언하지 않은 redden 은 redden 이 아니다** — 초록의
  원인이 "수정이 살아있다"인지 "변이가 죽었다"인지 구분이 안 된다.
- **#173 (소스에 실제 NUL 바이트가 들어가 `grep` 이 파일을 통째로 건너뛰었다)**: 경고 키를
  `'$groupId $columnKey'` 로 쓰려다 생성 스크립트를 거치며 **진짜 0x00 6개**가 파일에
  박혔다. `flutter analyze` 초록, `flutter test` 초록 — Dart 는 문자열 안의 NUL 을 문제삼지
  않는다. 그런데 `grep -n` 이 `Binary file ... matches` 만 출력한다. **이 저장소의 규율은
  "트리를 grep 한다"인데, 그 트리에서 파일 하나가 사라진 상태였다.** 게이트로는 절대 안
  잡힌다. 구분자는 `|` 로 충분하다.
