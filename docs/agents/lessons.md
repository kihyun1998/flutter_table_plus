# Lessons — flutter_table_plus 실증

이 repo 가 `theflow` 의 각 단계에서 실제로 **무엇을 놓쳤나** 의 기록 — 규칙에 무게를
주는 근거. 전부 이 repo 에서 실제로 일어났다. 단계 번호는 `theflow` SKILL.md 와 일치.
바인딩(`theflow.md`)이 추상으로 읽히면 여기 사건과 대조하라. 새 실증은 해당 단계 밑에.

---

## Step 1 — 이슈 먼저 (관찰은 적고, 진단은 확정하지 마라)

이슈 본문은 *관찰을 적는 곳*이지 원인을 단정하는 곳이 아니다. 확정한 진단이 틀리면 다음
사람이 그걸 믿고 엉뚱한 데를 판다.

- **#55**: "playground 가 800×600 테스트 표면에 안 맞으니 뷰를 키워라" 라고 못박았다.
  2000×1200 으로 키워도 실패 — 설정 패널이 `width: 380` 고정이라 제약은 `0<=w<=305` 그대로.
  진짜 원인은 테스트 폰트였다(Step 2).
- **#62**: "섹션이 안 접히니 #59 로 먼저 위젯을 갈라야 한다" 라고 썼다. `buildSection` 은
  **이미 `ExpansionTile`** 이었다 — 파일 *줄 수*만 보고 *내용*을 안 읽은 결과. 정정하고
  blocker 를 뗐다.
- **#65**: "오버플로가 12 곳" 이라 추정했다. 실패 스택을 소스 줄로 집계하니 **34 건이
  정확히 두 줄**(공용 헬퍼 둘)에서 났다. **결함 수는 인스턴스 수가 아니다.**
- **#63**: 아무것도 단정하지 않고 *"#61 이 끝난 뒤 읽고, 결정을 이유와 함께 기록하라"* 로
  썼다. 넷 중 유일하게 맞았다 — **판단을 유예하는 이슈는 정당한 형태다.** 닫는 이슈엔
  재개 조건을 남긴다(닫힌 이슈는 검색되지만 읽히지 않는다).
- **#60 (위치가 의존성을 숨긴다)**: `_settings`/`_columns`/`context` 만 훑고 "순수하다" 고
  판단했으나, 옮기자 `_formatNumber`·`_getPerformanceColor` 가 없다고 했다. 둘 다 인자만
  받는 순수 함수였다. **위치가 의존성을 만들지 않는다 — 다만 숨긴다.** 옮기기 전 grep.

## Step 2 — 경계 / 우회 금지 (원인은 `pubspec` 바깥일 수 있다)

`just_tooltip`·`flutter_checkbox` 는 남의 코드가 아니다 — 소스는 `../` 에 있고 각자 트래커가
있다. 동작이 궁금하면 그 소스와 CHANGELOG 를 읽는다.

- **#33 (우회는 결함을 숨긴다)**: 행 툴팁이 `child` 앵커를 피해 `pointer` 로 우회했고 잘
  작동했다. 그래서 upstream 결함이 살아남았다 — just_tooltip 0.4.2 CHANGELOG: *"both known
  downstreams had independently adopted it as a workaround."* **우회가 잘 들을수록 결함은
  오래 산다.** 0.4.2 가 고치자 이 리포 여섯 곳의 근거가 한꺼번에 거짓이 됐다.
- **#88 → #96 (판정과 보고는 별개의 의무다)**: `MouseRegion.onEnter` 의 조상 억제는
  0.4.0(#22)이 *의도한 계약*이라 판정하고, 그릴 게 없는 툴팁을 지은 이쪽을 고쳤다 — 판정은
  옳았다. **그러나 upstream 에 보고하지 않았다.** just_tooltip 0.4.4 가 같은 지점을 자기
  결함으로 판정하며 적었다: *"Two packages had independently grown the same local guard
  rather than report it."* 잘 드는 우회가 그 침묵을 정당해 보이게 만들었다. 로컬 가드는 이제
  제거됐고(#96) `^0.4.4` floor 가 그 자리를 대신한다 — **재도입 금지.**
- **#69/#38 (양방향 막)**: upstream 이 Flutter 3.13 을 요구하자 이쪽 `environment` 가 따라
  올라가야 했다. 변경은 아래로만 흐르지 않는다. `^0.4.0` 은 0.4.2 를 이미 해석하므로
  `>=3.10.0` 선언이 3.10~3.12 사용자에게만 깨졌다 — `pub get` 성공은 제약이 정직하다는
  증거가 아니다.

## Step 3 — 설계 판단 코드 전에 / TDD RED→GREEN

- **#61 (무엇을 테스트 *안* 할지도 결정)**: 데모에서 hover 위치를 행동으로 검증하지 않기로
  했다 — 패키지 `test/tooltip_anchor_test.dart` 가 이미 다섯 테스트로 못박고, 데모가 다시
  하면 폰트·클램프 함정을 데모 픽스처에서 또 상대해야 한다. 데모의 책임은 테마 조립이지
  just_tooltip 이 위치를 잘 잡는 것이 아니다.
- **#62 (구조가 걸리면 먼저 말한다)**: "라벨로 컨트롤 필터링" 은 `children` 이 이미 만들어진
  `Widget` 이라 불가능했다 — **`Widget` 은 자기가 무엇인지 말해주지 않는다.** 세 안을
  제시하고 사용자가 고른 뒤 코드를 시작했다.
- **#51 (우연한 초록 의심)**: 헤더 앵커 테스트가 red 였지만 원인은 배선이 아니라 픽스처였다
  (헤더 라벨과 셀 값이 같은 문자열). 고치니 이번엔 툴팁이 `screenMargin` 에 클램프돼 앵커와
  무관하게 중앙에 떴다(`Actual: 344`). 뷰포트 2000px + 컬럼 우측 이동으로야 올바른 이유로 red.
- **#58 (앞질러 구현 마라)**: Slice 1 최소 구현에 `onTap` 을 미리 넣었더니 Slice 2 가 처음부터
  green. `onTap: null` 로 되돌려 물리는지 확인해야 했다.
- **#52 (green 이면 되돌려 red)**: `scaledBy` 가드를 먼저 쓰자 `Expected: same instance,
  Actual: null` — #50 의 실패 모드가 글자 그대로 재현됐다. **되돌릴 땐 `git checkout --
  <file>` 금지**(미커밋 변경 다 날림) — `git stash push -- <file>` / `pop`.

## Step 4/5 — 증명 & 테스트 신뢰 (구분력 + 옳은 이유)

- **테스트 폰트는 글자당 `fontSize` 정사각형** — 오버플로가 화면보다 훨씬 쉽게 난다. #55:
  19자×16 = 304 vs 실제 ~190. **성가신 게 아니라 텍스트 폭 최악 경우 시뮬레이터** — 접근성
  확대가 도달할 자리를 미리 밟는다.
- **#58 (`find.text` 는 화면 어디든 잡는다)**: 홈이 없는데 `find.text('Playground')` 가
  통과 — `settings_panel.dart` 헤더가 같은 문자열을 그린다. 흔한 단어 단언은 아무것도 말 안 함.
- **#59 (이름이 아니라 개수를 세라)**: 컨트롤 68 개를 `Switch 25 / Dropdown 12 / Slider 20`
  개수로 덮었다. 이름으로 못박았다면 섹션 이동마다 테스트를 고쳐야 했고 "안 바뀌었다" 는
  순수성 증거가 사라졌다. 개수는 20→21 로 정직하게 깨진다.
- **#62 (관찰 지점을 화면에)**: `find.byType(ExpansionTile)` 은 위젯을 갈아끼우자 즉시
  깨졌고, `find.byIcon(Icons.expand_more)` 는 살아남았다. **리팩터 생존은 관찰 지점 위치로
  결정된다.**
- **#50/#52 (의미 가드 ≠ 회귀 가드)**: `scaledBy leaves an unset X tooltip theme unset` 은
  수정 없이도 통과한다(필드를 떨어뜨려도 `null`). 회귀를 잡는 건 `carries ... through
  untouched` 쪽. 커밋 메시지에 어느 쪽인지 적는다.
- **순수 이동 전 특성화 테스트 = 발견 도구.** #59: 그걸 쓰다 `ExpansionTile` 존재와 오버플로
  34 건을 찾았다. 리팩터 전 사진 한 장이 #59(그물)·#65(red 장치)·#62(계약)로 세 번 값했다.
- **#50 (그물 치지 말고 절벽 없애라)**: `scaledBy()` 가 `TablePlusTheme` 필드를 손으로
  나열해 재구성하다 `rowTooltipTheme` 를 잃었다. 리뷰가 지적해 `copyWith` 위에 다시 썼다 —
  스케일하는 여섯 필드만 부르니 나머지는 열거되지 않아 떨어뜨릴 수 없다. `scaledBy(1.0)` 이
  수신자를 그대로 돌려줘 버그가 안 보였다.

## Step 6 — 정합성 스윕 (틀린 근거 > 틀린 결론)

- **#69 (근거가 틀리면 아무 테스트도 안 깨진다)**: just_tooltip 0.4.2 가 `child` 를 *보이는*
  조각에 앵커하도록 고치자 여섯 곳의 *"행 중앙이 화면 밖으로 스크롤된다"* 가 거짓이 됐다.
  결론(`pointer` 필요)은 그대로 — `child` 는 이제 보이는 조각의 중앙(커서와 무관)을 겨냥한다.
  근거를 안 고치면 다음 사람이 *"버그 고쳐졌으니 `pointer` 빼도 되겠네"* 로 간다.
- **#96**: 0.4.4 가 empty-message 규칙을 upstream law 로 만들자, 다섯 호출처·`THEMING.md`·
  테스트 주석 둘에서 *"그릴 게 없는 툴팁은 짓지 마라"* 근거를 회수했다.
- **#51/#52 (제약은 사라질 때 지운다)**: #51 이 "헤더와 셀이 anchor 를 공유한다" 를 적었고
  #52 가 그걸 지웠다. lockfile: `example/pubspec.lock` 이 어디에도 없는 `2.16.0` 을 기록했다.

## Step 7 — 게이트 & 릴리스

- **#55 (`cd example && flutter test` 도 게이트)**: `flutter create` 카운터 템플릿이 그대로
  남아 역사상 계속 빨간불이었다. 영구히 빨간 테스트는 없는 것보다 나쁘다 — 무시하도록
  훈련시키고, 진짜 깨진 날 그걸 가린다.
- **2.15.0 발행/태그 사고**: 사용자가 발행했는데 확인하지 않았고, 그 뒤 **발행된 CHANGELOG
  항목을 제자리 수정하고 `v2.15.0` 태그를 두 번 옮겼다**. pub.dev 는 발행 시점 스냅샷을
  박으므로 repo 와 pub.dev 가 갈라졌다. 복구: 절을 발행본으로 되돌리고, 태그를 발행 트리로,
  범프는 새 `2.15.1` 절로. 또한 머지 안 된 PR #69 를 모른 채 태그해 `^0.4.0` + `>=3.10.0`
  조합이 3.10~3.12 에서 깨지는 트리였다 — **릴리스 전 열린 PR·로컬 브랜치를 확인한다.**
- **발행 커밋은 아카이브로 특정한다** — 시각 추정 금지. 아카이브 CRLF vs git blob LF 이므로
  `tr -d '\r'` 정규화. **모든 후보가 실패하거나 전부 성공하면 후보가 아니라 검사기를 의심.**
